# 配置 LLM Judge：平台额度与自带 API Key

平台评审模型与用户 Agent 自己调用的模型是两条链路。本页配置的是平台对任务证据进行评分时使用的模型；Agent 自己的模型费用不纳入平台账本。

## 两种使用方式

| 方式 | 谁提供 Key | 谁承担供应商费用 | 是否扣平台额度 |
| --- | --- | --- | --- |
| 平台模型 | 管理员 | 平台 | 是，按平台公示人民币价格版本扣减 |
| 自带 Key（BYOK） | 用户本人 | 用户自己的 API 账户 | 否，平台余额为零也能使用 |

正常通过管理后台创建的新用户默认获得 **¥5.00 累计平台评审额度**。这不是现金余额，不涉及在线充值或支付，不按周期恢复。管理员可按人民币金额追加或调减；不能扣减已消费或已预留的金额。

自带 Key 不受平台金额额度限制，仍受请求大小、超时、并发、执行次数和存储等资源限制，也受供应商自身余额和限流约束。

## 用户：接入自己的模型

1. 登录工作空间，打开“评审模型”。
2. 在“接入我的模型”填写三个字段：模型名称、API 地址、API Key。
3. 保存后，在创建 LLM 评测器或复制 Judge 模板时选择该模型，发布评测器及套件版本后运行实验。

例如：

```text
模型名称：deepseek-flash
API 地址：https://api.deepseek.com
API Key：在网页密码框中填写自己的 Key
```

可填服务根地址、`/v1` 地址或完整 `/chat/completions` 地址，平台自动补全请求路径。API Key 加密保存，保存和查询响应不返回 Key，也不会发送给用户 Agent SDK。

模型只对本人工作空间可见，其他用户和管理员的模型列表不会展示它。服务端会再次校验模型归属；即使知道模型 ID，也不能借用其他工作空间的 Key。本人可以停用自己的模型。

目前三字段接入已核验的模型预设是 `deepseek-flash` 和 `deepseek-v4-pro`，不猜测未知模型的参数或价格。其他模型需要维护者先增加预设。官方 DeepSeek 地址开箱允许；其他代理域名仍需部署者在 `MODEL_ENDPOINT_ORIGINS` 中明确允许，不能用私有 Key 绕过平台出口控制。

## 管理员：添加平台提供的模型

在“管理后台 → 模型配置”填写同样三个字段。平台提供的简化 DeepSeek 接入使用官方服务地址，避免把代理的自定义价格误当成官方价格。

模型名称、输入上界、输出上限、请求字节、并发和价格都由后端预设，不接受用户浏览器提交价格覆盖。DeepSeek 使用 `max_tokens`，并明确关闭思考模式，以便按非思考模式默认输出预算进行 JSON 评审；普通兼容客户端保留既有参数行为。

创建模型配置不会调用供应商。管理后台的“测试”按钮会真实请求 API，按平台模型的费用规则使用管理员本人的额度；创建评测器模板不会调用模型。

如果测试提示“账户的额度单位与模型计价单位不一致”，说明账户仍为历史credits，而模型使用人民币价格，或反过来；请求在调用供应商之前被拒绝，不能据此判断Key是否有效。使用自带Key时请改到工作空间“评审模型”接入；测试平台模型则需先为管理员本人准备人民币额度。无余额/流水的旧空钱包可通过“管理后台 → 账户与额度”选择本人并调整人民币金额完成初始化，已有历史账目的钱包不能直接改单位。

## 当前内置价格与默认限制

内置表于 **2026-10-27** 核验，使用 [DeepSeek 官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 的**峰时、缓存未命中标准价**，固定到不可变价格版本：

| 模型 | 输入（元/百万 Token） | 输出（元/百万 Token） |
| --- | --- | --- |
| deepseek-flash | 2 | 8 |
| deepseek-v4-pro | 9 | 27 |

**这是平台额度使用的公示标准价，不是实时读取供应商账单。当前不按缓存命中或闲时优惠折扣结算平台额度，可能与平台实际支付给供应商的账单不同。** 供应商改变价格后应更新预设并创建新配置；历史价格版本不变。自带 Key 的实际价格始终由用户与供应商约定，平台不代扣。

DeepSeek 预设采用 1,048,576 输入 Token 安全上界、8,192 最大输出 Token、65,536 请求字节和 2 个模型并发。模型上界与一次 Judge 实际预算不同：Judge 模板通常只申请最多 500 输出 Token。界面无需手动填写这些工程参数。

## 额度怎样扣减

内部使用整数微元：`1 元 = 1,000,000 微元`，避免浮点金额误差。浏览器通过十进制整数字符串/BigInt 处理，页面展示人民币。

平台模型调用前预留其输入上界和本次最大输出所需金额；可信用量返回后，按固定标准价结算并释放差额。余额不足以覆盖下一次预留时，进入等待额度状态，不向供应商发送新请求。**余额可能尚未为零就不足以覆盖预留**，尤其是上下文上界较大的模型；这是保守预留，不是已经消费了该金额。

例如 flash 的 1,000 输入与 1,000 输出 Token，当前标准价扣减 `¥0.01`。新用户 ¥5.00 不代表固定数量的 Token，不同模型及输入输出比例对应不同用量。

自带 Key 调用记录平台扣款为 0，不建立平台金额预留或消费流水，但仍记录模型响应、Token 用量和执行状态。断线后的未知调用保持同一调用身份，不自动重发；自带 Key 不代表可以无条件重试已可能收费的请求。

## 历史版本兼容

升级不会把旧 credits 账目重新标成人民币，也不会给现有用户重复发放新用户额度。历史账户仍显示 credits，旧模型保持原价格含义。旧 credits 与新人民币价格不能混扣。

没有任何流水、余额为零的旧账户，管理员可通过人民币额度调整入口初始化其人民币账户。已有历史账目的账户需要单独制定迁移方案，不能直接改单位；在此之前仍可使用自己的 Key。

旧的管理员详细模型创建 API 和整数额度 API保留供兼容集成使用；需要明确创建人民币计价配置的维护者可指定 `billing_unit: CNY_MICRO`，价格数值以微元计。普通使用者只需要上述三字段页面。
