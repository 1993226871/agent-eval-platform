# 在工作台编写任务与评分规则

工作台使用“任务集”和“评分规则集”两个入口。任务集是一组要交给 Agent 的题目；评分规则集定义如何判断答案与执行过程。创建实验时选择 Agent、任务集版本和评分规则集版本。

## 创建任务集

1. 进入“任务集”，点击“新建任务集”，填写名称并创建草稿。
2. 点击“新增任务”，填写任务要求，例如“查询订单 A 并说明状态与金额”。
3. 在“输入”中选择数据类型。对话 Agent 可以使用文本，也可以使用字段组，例如字段名 `question`、值为提问内容；订单示例使用字段 `order_id`、值为 `A`。这些字段要与 Agent 代码读取的输入一致。
4. 如需参考答案，勾选“提供参考答案”，按文本、数字或字段组填写。参考答案供评分器使用，不会作为任务输入发送给 Agent。
5. 设置任务超时，继续添加其他任务。点击“保存草稿”，再点击“发布版本”。

字段组支持添加、改名、删除字段；列表支持逐项编辑。数字、是/否、文本和空值会保留各自类型，整个过程无需填写 JSON。

## 创建评分规则集

1. 进入“评分规则集”，创建一个草稿。
2. 点击“新增评分规则”，填写规则名称。
3. 从“评分方式”选择规则检查、LLM 评审（Rubric）或自定义 Python。
4. 设置通过分数、评分维度、权重和是否必须通过。至少一条规则必须设置为“必须通过”，每个使用的维度至少需要一条权重大于零的规则。
5. 添加其他规则，保存草稿后整体发布版本。

### 规则检查

适合确定的条件，例如字段相等、数值比较、是否调用指定工具、工具参数和耗时检查。

例：Agent 返回字段组 `{amount: 100, status: paid}`，任务参考答案也是同样的字段组。

- 检查条件：等于。
- 检查对象来源：Agent 最终输出；字段路径：`amount`。
- 期望值来源：任务参考答案或输入字段。
- 期望对象来源：任务参考答案；字段路径：`amount`。

这样每道任务可以使用自己的参考金额，不需要为每个金额建立一条规则。字段路径留空表示检查整个值；子字段使用 `/` 分隔，例如 `order/amount`。

### LLM 评审与 Rubric

先在“评审模型”接入模型，再在规则中选择它。填写一个明确的评分目标，以及 0、1、2、3、4 分各自的判定标准。例如，目标是“回答是否忠实于订单查询结果”，0 分表示编造或矛盾，4 分表示完整准确且无编造。

Rubric 是 LLM 使用的等级标准，不是另一个执行引擎。平台将 0–4 分换算为 0–1，再与通过分数比较。默认通过分数 0.75 对应至少 3 分。

平台模型消耗个人平台额度；自带 API Key 的模型由供应商计费。轨迹判断依赖 SDK 上报的证据，缺少证据会显示证据不足，不能视为 Agent 零分。

### 自定义 Python

选择该方式后填写 `evaluate(context)` 函数。平台保留代码编辑区，因为这是用户主动选择的自定义编程能力。评分代码只能在合格的隔离 Runner 中执行；本机没有对应执行节点时无法使用。

## 草稿、发布与已有配置

草稿用于修改，发布版本用于实验。查看发布版本时仍使用同样的表单，但不能修改；需要调整时返回草稿，保存并发布新版本。

用户在一个页面配置多条规则，平台在事务中冻结各条规则和整个规则集。发布失败会回滚，不会留下半套新版本；同一修订重复发布返回已有版本。历史实验继续引用原来的固定版本。

已有评分套件可以直接在“评分规则集”中打开，它引用的评分规则会加载到表单。独立创建并发布过的评分规则，也可通过“从已有规则添加”加入新的规则集；修改只作用于当前草稿。

## 开始实验

启动自己的 SDK Worker，在“实验”点击“新建实验”，选择 Agent、任务集版本和评分规则集版本。启动后平台派发任务，Agent 执行并上报结果和轨迹，平台按规则集评分。

报告中的“执行状态”和“评分结果”分别表示程序是否完成任务，以及答案/过程是否满足标准。Agent 正常返回错误答案，可以是执行成功但评分未通过。
